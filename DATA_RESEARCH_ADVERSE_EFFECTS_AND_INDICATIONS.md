# PolyGuard: obtainable adverse-effect and indication data

**Checked 3 October 2026 (Asia/Kolkata).** This is a source and engineering audit, not a clinical validation. Links below point to pages, documentation, APIs, or files actually opened through web fetch unless explicitly marked **binary not fetched** or **search-index only; live fetch failed**. Direct HTTPS from this workspace was refused (`WinError 10061`); no remote dataset was downloaded and **no remote-to-1,902-drug join rate was measured**. Web fetch could open HTML, text, and one openFDA JSON sample, but returned unsupported-content errors for gzip/CSV binaries and some API queries. Only `research_scratch/` and this report were written.

## Executive decision

**Adverse effects:** ship a *provenance-first pair evidence layer*: (1) extract explicit, named pair outcomes from openFDA/DailyMed interaction-label sections, (2) add a small doctor-reviewed mechanism-rule library using FDA CYP/transporter examples and label evidence, and (3) run a bounded, clearly marked FAERS disproportionality pilot for the most-used DDInter pairs. Keep current individual-drug overlap as a separately labelled fallback. Do **not** import the attractive TWOSIDES/Decagon table into the public app until its redistribution and MedDRA-name rights are clarified. The defensible first release has **unknown pair coverage**; measure it after extraction, with 30 high-use drugs and 500 priority pairs as the pilot. A rule can cover a DDInter pair only if both ingredient roles and the specific outcome are documented. Display “reported with this pair” or “mechanism-based concern,” never “this combination causes X” from FAERS alone.

**Indications:** make [DrugCentral](https://drugcentral.org/download) the primary structured candidate generator, join through INN/synonyms and ingredient identifiers, use [ChEMBL drug indications](https://github.com/chembl/GLaDOS-docs/blob/master/web-services/chembl-data-web-services.md) and [MED-RT/RxClass](https://lhncbc.nlm.nih.gov/RxNav/APIs/api-RxClass.getClassMembers.html) as corroboration, and have an Indian clinician approve a **30-condition outpatient release** against [ICMR workflows](https://www.icmr.gov.in/standard-treatment-workflows-stws?q=ICa) and [MoHFW guidelines](https://clinicalestablishments.mohfw.gov.in/en/standard-treatment-guidelines). Two records copied from ChEMBL and Open Targets count as **one underlying source**, not consensus. Target 30 reviewed conditions and publish their observed vocabulary coverage/precision, not an assumed percentage. Approximate effort: **100–160 engineer hours for pair evidence + 70–110 engineer hours and 8–15 clinician hours for indications**, excluding licence clarification and ongoing updates. These are planning estimates, not measurements.

### FAERS calculation that survives questions

Use **bulk quarterly event files** for research precomputation, not one live API query per 130k pair. Normalize ingredient strings, preserve report version, deduplicate by `safetyreportid`/latest version, and flag suspect versus concomitant roles. For pair A+B and event E, tabulate pair-exposed E/non-E and reference E/non-E within a stated report universe, stratified by year (and optionally age/sex/country where sufficiently populated). Compute PRR = `[a/(a+b)]/[c/(c+d)]`, confidence interval or empirical-Bayes shrinkage, pair report count `a`, and compare to A-alone and B-alone signals. Pre-register a minimum count (e.g. **a ≥ 5** for pilot display), adjustment/suppression for duplicates, indication bias, stimulated reporting, time trends, and masking. A signal **does not estimate incidence** because FAERS has no exposure denominator, and multiple drugs on one report do not identify the causal drug. [Event-result structure](https://open.fda.gov/apis/drug/event/understanding-the-api-results/), [sample result](https://api.fda.gov/drug/event.json?limit=1&search=receivedate:%5B20040101+TO+20081231%5D), [openFDA warning and CC0 terms](https://open.fda.gov/terms/) checked 2026-10-03. MedDRA strings present in reports still deserve a terminology-rights review before compiling a large reusable MedDRA dictionary.

**Indication consensus rule.** Import all records into a staging table, then collapse common origins. Suggested evidence families: (A) approved label/DrugCentral, (B) independently curated MED-RT, (C) Indian ICMR/MoHFW named regimen reviewed by a clinician, (D) ChEMBL regulatory reference; Open Targets↔ChEMBL and repoDB↔DrugCentral are *same-family echoes*. Tier **Established** = a current approval/label or named Indian guideline **plus independent corroboration or clinician sign-off**. Tier **Supported single-source** = one credible structured source, held for review or shown only with source label. Tier **Symptomatic**, **Preventive**, **Trial/investigational**, **Historical/uncertain**, and **Contraindicated for this disease** remain separate. No automatic “≥2 sources” rule can replace indication context, formulation, age, or stage. PharmacotherapyDB's own curators disagreed on **444 of 1,388** candidate rows, demonstrating why a concise review queue is necessary. [Primary curation account](https://think-lab.github.io/d/182/) checked 2026-10-03.

**Licence packaging:** DrugCentral is CC BY-SA **4.0**, ChEMBL is CC BY-SA **3.0**, WHO EML is CC BY-NC-SA **3.0 IGO**, and DDInter is CC BY-NC-SA **4.0**. These are different obligations; a single blended database should not be marked simply “CC BY” or “open.” Preserve record-level source and licence, keep WHO/uncleared guideline material in the internal review workspace, and have the final combined artifact's adaptation/share-alike terms checked before public release. FDA CC0/openly authored facts can be stored separately. This is a release gate, not an assumption that all source licences automatically interoperate. [DrugCentral licence](https://drugcentral.org/privacy), [ChEMBL licence](https://www.ebi.ac.uk/chembldb/), [WHO rights](https://www.who.int/copyright), [DDInter terms](https://ddinter2.scbdd.com/terms/) checked 2026-10-03.

### Doctor validation in minutes per condition

Export one **review workbook/CSV per specialty**, 20–60 rows at a time, sorted by disputed and high-impact items. Columns: `condition_id`, `condition_label`, `ingredient_id`, `generic_name`, `relation` (treat/palliate/prevent), `proposed_tier`, `source_ids`, `source_urls`, `source_versions`, `exact_evidence_summary`, `India_availability`, `formulation_route`, `age_pregnancy_renal_limits`, `disagreement_flag`, `decision` (Keep/Remove/Modify/Add), `replacement_or_note`, `reviewer_name`, `qualification`, `review_date`, `guideline_version`. Give the clinician 20 minutes per specialty session: first review conflicts/negative controls, then 10 randomly selected accepted rows; defer every uncertain row. Invite two independent reviewers only for disputed high-risk specialties. Importer rejects missing reviewer/date/evidence, preserves before/after JSON and a content hash, and never records patient data. An in-app “Suggest correction” exports a de-identified row to a CSV review queue; **no patient/medication-plan payload**.

For a publishable quality check, pre-register 10 gold-standard diseases (e.g. hypertension, type 2 diabetes, heart failure, CKD, hypothyroidism, asthma, COPD, UTI, depression, epilepsy). Two clinicians independently list acceptable generic medicines **with line of therapy/formulation**, adjudicate differences, then calculate precision, recall and false-positive severity for the automated tiers and for the signed-off release. Report disease-level values and macro average, sample sizes and exclusions. Do not call an essential-medicines list a gold standard for every approved indication. A 20-minute review is realistic for a curated queue, **not** for raw dump review.

## Implementation plan and compact artifacts

1. **Inventory and permissions (8–16 h).** Freeze source URLs, version/date, hash, source licence, and what will be redistributed. Get explicit answer from the Tatonetti lab for TWOSIDES/SNAP and verify MedDRA name rights before adding either. Audit whether the existing local DDInter-derived severity artifact's CC BY-NC-SA attribution/share-alike obligations are satisfied. Keep any licensing-uncertain text out of git.
2. **One normalized ingredient table (16–25 h).** Script `build_ingredient_crosswalk.py`: canonical `polyguard_drug_id`, INN, aliases, salt/ester/route, DrugBank ID (identifier only), RxCUI, PubChem CID, ChEMBL parent, DrugCentral ID, UNII, InChIKey, match method, confidence and manual override. Exact normalized names first; resolve structures via PubChem/UniChem, never auto-merge enantiomers or combinations. Emit `unmatched.csv` and `ambiguous.csv`; record matched/1,902 by source and 95% CI for a manually audited sample.
3. **Extract pair assertions (45–70 h).** `extract_label_ddis.py` reads latest SPL label version/SETID, matches ingredient B in A's interaction section, extracts outcome/management, handles negation, hypothetical language, tables, and “avoid/monitor/reduce dose”; reciprocal evidence is a confidence boost, not a requirement. `build_mechanism_rules.py` joins FDA tables and locally curated pharmacodynamic lists with role/dose/route restrictions. Never manufacture a named adverse effect from a CYP relation alone. Store source URL and text-span hash in a **non-shipped** audit table.
4. **FAERS pilot (45–80 h, optional for first UI release).** `build_faers_signals.py` processes bulk events for 500 nominated priority pairs, generates report counts, PRR/interval and both single-drug comparisons, and marks all results `signal_not_causal`. A physician/pharmacist reviews the top 50 signals and 50 random negatives before display. Stop if false-alert burden is unacceptable.
5. **Indication staging (45–70 h).** `import_indications.py` reads DrugCentral, ChEMBL, MED-RT; maps disease IDs through MONDO/MeSH/DO and hand-reviewed colloquial aliases. `score_indications.py` groups source lineages, separates indication types and creates doctor CSVs. `import_reviews.py` creates signed audit history. ICMR/MoHFW references are clinician-reviewed evidence, not scraped/reprinted guideline paragraphs.
6. **Release gates (20–35 h).** `measure_coverage.py` reports: source drug match/1,902; named direct-label pair count/130,422; rule pair count/130,422; FAERS signal count/130,422; overlap by tier; 30-condition disease and drug counts; clinical-review rejection rates. Test high-risk and tricky pairs (warfarin–NSAID, ACE inhibitor–spironolactone, macrolide–QT drug, rifampicin–substrate), plus false-positive controls and combinations/salts. Lock build if licences, provenance, pair attribution, or size gate fail. Re-run quarterly, and after guideline/label changes.

**Proposed public artifact schema** (illustrative, not yet built):

```json
{
  "version": "2026-10-03-pilot",
  "source_manifest": [{"id":"fda_label","url":"https://open.fda.gov/apis/drug/label/","retrieved":"YYYY-MM-DD","license":"CC0-with-exceptions"}],
  "effects": {"e17":{"name":"hyperkalaemia","terminology":"plain_clinical_term"}},
  "pairs": {"drug_001|drug_002":[{"effect":"e17","tier":"label_statement","source_ids":["spl:SETID:VERSION"],"evidence":"named_in_label","reports":null,"prr":null,"limitations":["US_label"]}]},
  "rules": [{"id":"acei_k_sparing","roles":["ACE_inhibitor","potassium_sparing_diuretic"],"effect":"e17","tier":"mechanism_reviewed","source_ids":["spl:SETID:VERSION"],"reviewer":"...","reviewed":"YYYY-MM-DD"}]
}
```

Prefer stable integer ingredient/effect IDs and a dictionary, keep only top **3–5 independently supported effects per pair** (rank by evidence tier, not PRR alone), and store counts/PRR only for actual FAERS rows. A planning budget of **≤20 MB pair/effect JSON plus ≤5 MB indication JSON and ≤5 MB manifest/crosswalk** meets the 30 MB git target; this is an engineering *gate*, **not a measured output size**. Use compact JSON separators and gzip for deployment, check raw committed bytes too. With 130,422 pairs × 3 effects × ~20–35 packed bytes, the per-effect portion alone is roughly 7.8–13.7 MB before pair keys/dictionaries/metadata; if actual build exceeds 30 MB, retain only evidence-bearing pairs and compress/partition, never remove provenance. Unmatched pairs show “No pair-specific evidence in PolyGuard's current sources” plus separately titled individual-drug effects, not “safe.”

**Indication JSON row**: `{condition_id, display_name, aliases, external_ids, drug_id, relation, tier, line_of_therapy, formulation_route, restrictions, source_evidence:[{source, record_id, url, version, relation_type}], reviewer:{name, date, decision, review_batch}, build_version}`. Public release includes only `Keep`/`Modify` rows. Keep review emails and patient feedback outside shipped JSON. Surface evidence tiers beside each medicine, show guideline/label date, and let a doctor filter by India-reviewed, approved-label, preventive or symptomatic use. A list entry never implies suitability for this individual patient.
